# Vault Daydream

## Required Context

- Start at `Vault Index.md` in the vault defined in `AGENTS.md`; use `README.md` for filing guidance.
- For infrastructure, servers, services, agents, automation, roadmap, or company/project context, follow the vault reading order in `AGENTS.md`: `homelab/`, then `future/`, then `biz/`, then other folders.
- Prefer specific references from existing notes over generic brainstorming.
- If a note is missing or stale, say what is missing instead of inventing details.

## Workflow

1. Infer the topic and requested output from context; ask only when a missing constraint would materially change the directions.
2. Read relevant vault notes before proposing anything.
3. Extract constraints, live systems, existing plans, people, brands, and recurring themes.
4. Generate a small set of concrete directions, not a long list of shallow ideas.
5. Tie each direction back to observed vault context.
6. Record confirmed changes to systems or organizational arrangements in the corresponding note. File requested ideas as proposals, not decisions, and link new notes from the matching index. Do not invent dates, attendees, owners, deadlines, or completion status. `future/` is Future / FutureRP, not general future plans; follow documented access rules for any live checks.

## Output Style

- Lead with the most actionable direction.
- Separate confirmed facts from speculation.
- Include next steps only when they are specific and useful.
